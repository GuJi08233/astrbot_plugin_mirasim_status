# astrbot_plugin_mirasim_status

监控 [Mirasim 官方状态页](https://mirasim.ai/status) 上各模型的可用性：用 `/mirasim` 一键查看状态（默认渲染成图片卡片），也可以让某个会话订阅模型，在状态变化时自动收到推送。

数据来自官方接口 `https://mirasim.ai/api/status`，按 cohort（free/paid/cloud）→ agent（Claude/GPT/Kimi/…）→ model 三层组织，每个模型在不同池子各有一份数据。插件只读取官方接口，不会向模型发送任何请求。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/mirasim` | 查看模型状态（图片卡片）。插件配置里填了「默认展示的模型」时只显示这些模型 |
| `/mirasim all` | 查看全部模型，忽略上面的配置 |
| `/mirasim <模型>` | 查看单个模型在 free/paid/cloud 三池的详情：当前状态、p50/p95、24h/7d 可用率、最近 24h 历史 |
| `/mirasim <模型>@<free\|paid\|cloud>` | 只看该模型在指定池的详情 |
| `/mirasim sub <模型>` | 订阅该模型全部池的状态变化推送 |
| `/mirasim sub <模型>@<池>` | 只订阅指定池 |
| `/mirasim sub all` | 本会话订阅全部模型，包括之后新增的模型 |
| `/mirasim unsub <模型>[@池]\|all` | 取消订阅 |
| `/mirasim list` | 查看本会话订阅了哪些 |
| `/mirasim help` | 显示指令说明 |

模型名可以只写能唯一确定的一部分，例如 `opus-5-5` 即 `claude-opus-5-5`；匹配到多个模型时会列出候选。池子可以用英文 ID 或中文别名（免费/付费/云端）。子命令也可以用中文：`订阅`、`取消订阅`（`退订`）、`订阅列表`、`全部`。

## 状态分级

可用率（最近 15 分钟或 1 小时）决定状态：

| 可用率 | 状态 | 图标 |
| --- | --- | --- |
| ≥ 90% | ✅ 正常 | 🟢 |
| 50–89.9% | ⚠️ 不稳定 | 🟡 |
| < 50% | ❌ 中断 | 🔴 |
| 暂无数据 | ❔ 无数据 | ⚪ |

比官方页面（≥99% / 95–99% / <95%）宽松，避免把轻微波动当成异常。24h 历史图按同样阈值逐格染色。

## 图片卡片

`/mirasim` 和 `/mirasim all` 的概览默认渲染成图片：每个模型一组，下面 3 行分别对应免费池、付费池、云端池，每行带最近 24 小时 48 格历史条（30 分钟一格，旧 → 新，绿/黄/红/灰）。

- 渲染走 AstrBot 的文转图服务，即全局配置里的 `t2i_endpoint`（默认官方服务，也可以填自建的 [astrbot-t2i-service](https://github.com/AstrBotDevs/astrbot-t2i-service)）。
- 渲染出错，或文转图服务返回的不是图片时，自动改发文字概览，日志里会有一条 `[Mirasim] Image render failed` 或 `non-image body` 警告。
- 卡片宽 580px、按 1.8 倍像素比输出 PNG，手机上点开大图时文字仍清晰。
- 单个模型详情和状态推送始终是文字。不想要图片可以在配置里关闭「状态概览以图片发送」。

## 状态推送

订阅以**会话**为单位：在群里订阅，推送发到这个群；私聊订阅则发到私聊。

```
Mirasim 状态变化
🔴 claude-opus-5-5（免费）中断 (限流79%·故障21%)（可用率 0%，16:00 起）
```

```
Mirasim 状态变化
🟢 claude-opus-5-5（免费）已恢复，p50 4.2s，可用率 100%，中断持续约 3小时
```

- **防抖**：模型连续 N 次轮询（「状态变化确认次数」，默认 2）的 now.status 一致才算状态变化。官方接口每分钟聚合一次，默认配置下推送最多比实际晚约 1 分钟。
- **合并**：同一轮检测里的多个变化合并成一条消息发送。
- **时间**：括号里的「起」是故障开始的格点时间（30 分钟粒度）；恢复消息里的故障时长同样按格点计算，最坏情况是 30 分钟精度。
- **重启**：每个模型在每个池的上次状态会持久化。重启或重载插件后，期间发生的变化会在下一轮轮询时补推；首次安装时只记录当前状态作为基线，不会推送。
- **首轮轮询**：插件加载后等待一个轮询间隔才开始第一次检查，以免平台适配器尚未连上导致推送丢失。`/mirasim` 等指令不受影响，随时实时查询。

> QQ 官方机器人（qq_official）不支持主动发送消息，在这类会话里订阅收不到推送；NapCat 等 OneBot 协议端、Telegram 等平台不受影响。

## 配置项

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `api_url` | 状态接口地址 | `https://mirasim.ai/api/status` |
| `render_image` | 状态概览以图片发送，失败时自动回退文字 | `true` |
| `display_models` | `/mirasim` 默认展示的模型，每项可写：<br>· 模型 ID（如 `claude-opus-5-5`）— 显示该模型的全部 3 个池<br>· `模型@池`（如 `claude-opus-5-5@paid`）— 只显示指定池<br>两种形式可混合，对同一模型给出多条 `@池` 会堆叠显示这几个池。找不到的项会在回复末尾列出。留空则展示全部。 | 空 |
| `poll_interval` | 后台轮询间隔（秒），最小 60 | `60` |
| `confirm_samples` | 状态变化确认次数，设为 1 则每次翻转都推送 | `2` |

请求跟随 AstrBot 的全局代理设置（设置 → 网络 → `http_proxy`）。显示的时间使用 AstrBot 所在机器的时区，Docker 部署请确认设置了 `TZ` 环境变量（如 `TZ=Asia/Shanghai`）。

## 测试

在 AstrBot 根目录运行。`ASTRBOT_ROOT` 指向临时目录，避免导入 AstrBot 时改动真实的 `data/`：

```bash
ASTRBOT_ROOT=/tmp/mirasim_test uv run python -m unittest data.plugins.astrbot_plugin_mirasim_status.tests.test_main
```
