# astrbot_plugin_mirasim_status

监控 [Mirasim 模型稳定性监控站](https://mirasim-status.521882.xyz/) 上各模型的可用性：用 `/mirasim` 一键查看状态，也可以让某个会话订阅模型，在模型故障或恢复时自动收到推送。

数据来自监控站的 `/api/status` 接口，插件只读取监控站已有的检测结果，不会向模型发送任何请求。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/mirasim` | 查看模型状态。插件配置里填了「默认展示的模型」时只显示这些模型 |
| `/mirasim all` | 查看全部模型，忽略上面的配置 |
| `/mirasim <模型>` | 查看单个模型详情：失败原因、响应耗时、连续可用时长、24h 成功率、最近 20 次采样 |
| `/mirasim sub <模型>` | 本会话订阅该模型的状态变化推送 |
| `/mirasim sub all` | 本会话订阅全部模型，包括之后新增的模型 |
| `/mirasim unsub <模型\|all>` | 取消订阅 |
| `/mirasim list` | 查看本会话订阅了哪些模型 |
| `/mirasim help` | 显示指令说明 |

模型名可以只写能唯一确定的一部分，例如 `opus-5-5` 即 `claude-opus-5-5`；匹配到多个模型时会列出候选。子命令也可以用中文：`订阅`、`取消订阅`（`退订`）、`订阅列表`、`全部`。

概览示例：

```
Mirasim 模型状态 · 可用 15/17
❌ claude-sonnet-5-5 · 上游 HTTP 503
❌ kimi-k3 · 上游输出被截断
✅ claude-opus-5-5 · 1.8s · 24h 62.1%
✅ deepseek-flash · 2.1s · 24h 100%
...
检测于 21:12 · 每 5分钟一轮
```

失败的模型排在最前面。状态含义与监控站一致：✅ 可用、❌ 失败、⏸️ 已过期（监控站超过 `stale_after_seconds` 没有检测，当前状态无法确认）、❔ 待检测。已退出监控目录的模型不出现在列表里，但仍可以用 `/mirasim <模型>` 查询其历史记录。

## 状态推送

订阅以**会话**为单位：在群里订阅，推送发到这个群；私聊订阅则发到私聊。

```
Mirasim 状态变化
🔴 claude-opus-5-5 故障：上游 HTTP 503（21:07 起）
🔴 kimi-k3 故障：上游输出被截断（21:07 起）
```

```
Mirasim 状态变化
🟢 claude-opus-5-5 已恢复，当前耗时 1.8s，故障持续约 2分钟
```

- **防抖**：模型最近 N 次采样（「状态变化确认次数」，默认 2）结果一致才算状态变化。监控站上偶发的单次失败或单次成功很常见，按实际数据统计，默认值能把推送量降到约三分之一，代价是推送最多比实际变化晚约 10 分钟。
- **合并**：同一轮检测里的多个变化合并成一条消息发送。同一上游的模型往往同时故障、同时恢复，不会刷屏。
- **时间**：括号里的「起」是故障实际开始的采样时间，不是推送时间；恢复消息里的故障时长同样按采样记录计算。
- **重启**：每个模型上次确认的状态会持久化。重启或重载插件后，期间发生的变化会在下一轮轮询时补推；首次安装时只记录当前状态作为基线，不会推送。
- **首轮轮询**：插件加载后等待一个轮询间隔才开始第一次检查，以免平台适配器尚未连上导致推送丢失。`/mirasim` 等指令不受影响，随时实时查询。

> QQ 官方机器人（qq_official）不支持主动发送消息，在这类会话里订阅收不到推送；NapCat 等 OneBot 协议端、Telegram 等平台不受影响。

## 配置项

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `api_url` | 状态接口地址 | `https://mirasim-status.521882.xyz/api/status` |
| `display_models` | `/mirasim` 默认展示的模型 ID，留空展示全部；找不到的 ID 会在回复末尾列出 | 空 |
| `poll_interval` | 后台轮询间隔（秒），最小 30。监控站每 5 分钟检测一轮，间隔再短也不会更早发现变化 | `60` |
| `confirm_samples` | 状态变化确认次数，设为 1 则每次翻转都推送 | `2` |

请求跟随 AstrBot 的全局代理设置（设置 → 网络 → `http_proxy`）。显示的时间使用 AstrBot 所在机器的时区，Docker 部署请确认设置了 `TZ` 环境变量（如 `TZ=Asia/Shanghai`）。

## 测试

在 AstrBot 根目录运行。`ASTRBOT_ROOT` 指向临时目录，避免导入 AstrBot 时改动真实的 `data/`：

```bash
ASTRBOT_ROOT=/tmp/mirasim_test uv run python -m unittest data.plugins.astrbot_plugin_mirasim_status.tests.test_main
```
